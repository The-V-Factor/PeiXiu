# PeiXiu 下一版本 PRD：摩托限行数据与路线规划体验优化

> 状态：已确认，待实施
>
> 目标版本：v0.1.0（暂定）
>
> 日期：2026-09-01

## 1. 背景

当前 `v0.0.1` MVP 已完成并部署到 `https://peixiu.pages.dev/`。路网 graph 已独立放入数据仓库并通过稳定 manifest 加载；但当前点位数据混合了普通交通监控与摩托车限制信息，不能直接用于核心路线判断，起点编辑能力不完整，地图用 tile 矩形表达范围，生产页面仍展示 Spike 入口。

本版本的目标是让数据发布、点位编辑和地图覆盖范围表达更接近真实产品，同时保持浏览器本地路线计算、广州范围和免费静态托管约束。

## 2. 产品目标

1. 以摩托车限行/禁行道路和区域为核心数据，避免用普通摄像头点位推断通行限制。
2. 明确属于摩托车闯禁抓拍的点位作为辅助证据数据，与货车、压线、违停和普通监控分开。
3. 起点和终点都可以重新选择或删除，地图交互状态清晰可控。
4. 使用广州行政区划边界表达产品范围，并使用真实路网覆盖范围表达当前可计算区域，重点补全南沙数据。
5. 正式页面隐藏技术 Spike 入口，但保留开发验证页面。

## 3. 范围与不做事项

### 3.1 本版本范围

- 使用独立数据仓库管理路网、摩托车限行规则、摩托车闯禁抓拍证据、边界和覆盖范围。
- 摩托车限行规则通过稳定 manifest 加载，数据文件使用固定版本。
- 仅在记录明确说明“摩托闯禁”或能由有效通告确认时，才进入摩托车相关辅助点位；普通交通监控不进入核心数据。
- 通过地图点击添加本地测试摄像头，支持多个点位和删除。
- 起点、终点均支持重新选择和删除。
- 加载并显示广州行政边界及真实路网覆盖范围。
- 重新构建或裁剪路网数据，使目标范围包含广州行政区内的南沙区域。
- 从正式导航页面移除 Spike 入口。

### 3.2 不做事项

- 不接入实时摄像头接口、后台管理或多人协作编辑。
- 不把普通机动车、违停、超速、闯灯、压线或货车抓拍点当作摩托车限行依据。
- 不把“抓拍点”自动扩大为整条道路的禁行规则；规则范围必须单独确认。
- 地图添加的测试摄像头不写入公共仓库或 CDN，仅保存在浏览器本地。
- 不引入远程 Routing API，不改变 `motorcycle` costing。
- 不把行政边界外的区域扩展为产品范围。
- 不把“避开已知摄像头”描述为合法通行或安全保证。
- 不删除 Spike 页面及其测试代码，除非后续 Issue 单独决定。

## 4. 功能需求

### 4.1 摩托限行数据与抓拍证据外置

数据仓库目录建议如下：

```text
routing/guangzhou/
  manifest.json
  coverage.geojson
  graph-.../

restrictions/guangzhou/
  manifest.json
  restrictions-....json

cameras/guangzhou/
  manifest.json
  motorcycle-enforcement-....json

boundaries/guangzhou/
  guangzhou-admin.geojson
```

摩托限行 manifest 使用稳定入口，数据文件使用不可变 commit 或版本路径。规则数据、抓拍证据和路网数据独立版本，更新其中一类不需要重新发布其他数据。

规则记录至少包含道路/区域、车辆范围、方向、时段、生效状态和几何表达。抓拍证据记录至少包含地点文字、坐标精度、车辆范围、执法行为和核验状态。没有明确摩托车限制依据的记录不得进入规则数据。

网页加载失败时，路线仍可计算，但必须明确提示未启用摄像头避让。

### 4.2 地图选点添加测试摄像头

页面提供“添加测试摄像头”入口。进入选点模式后，用户点击地图即可创建测试点，自动生成经纬度；名称、类型等信息为可选项。

要求：

- 支持连续添加多个测试点；
- 测试点使用区别于正式点位的视觉样式；
- 支持删除单个测试点和清空全部测试点；
- 测试点保存在 LocalStorage，刷新页面后仍可恢复；
- 测试点只影响当前浏览器的避让测试，不修改 CDN 数据。

### 4.3 起点和终点编辑

起点和终点各自显示以下操作：

```text
起点  坐标  重新选择  删除
终点  坐标  重新选择  删除
```

交互规则：

- 没有起点时，地图点击设置起点；
- 有起点、没有终点时，地图点击设置终点；
- 起点和终点都存在时，普通地图点击继续修改终点；
- 点击“重新选择起点”后，下一次地图点击修改起点；
- 删除任一点后，删除对应标记并清除旧路线和统计数据；
- 任一点改变后，必须重新规划才能产生新路线；
- “使用当前位置”仍然可以设置或重新设置起点。

### 4.4 广州行政边界与路网覆盖范围

本版本区分两类几何数据：

1. **广州行政边界**：定义产品范围，优先从广州市/广东省自然资源或政务开放数据取得；无法取得时再使用 OSM 行政边界数据，并保留来源和许可信息。
2. **路网覆盖范围**：根据实际可路由 graph 或其道路数据生成，表达当前真正可以计算路线的区域。

当前 graph 裁剪南界为 `22.95`，不足以代表完整广州，南沙必须作为数据重建和验收重点。不能只替换前端矩形描边来解决覆盖不足问题。

前端应使用 GeoJSON 图层显示边界和覆盖范围，不再根据 tile `bounds` 绘制单纯矩形。行政边界表示产品范围，路网覆盖表示可计算范围；两者不一致时要明确展示，不能暗示无路网区域可规划。

### 4.5 隐藏 Spike 入口

从正式页面导航中移除“打开技术 Spike”链接。Spike 页面和代码保留，开发人员仍可通过直接 URL 访问；如需彻底限制访问，另建 Issue 处理。

## 5. 数据与技术约束

- 路线计算继续在浏览器 Web Worker 中使用 Valhalla WASM。
- 不使用远程 Routing API 作为降级方案。
- 摄像头和边界数据使用公开静态资源分发，不引入需要绑定支付信息的存储服务。
- GeoJSON 使用标准 WGS84；MapLibre 坐标顺序保持 `[lon, lat]`。
- 数据 manifest 应包含区域、版本、来源、更新时间和固定数据地址，支持回滚。
- 行政边界、路网覆盖和摄像头数据都要保留来源、更新时间及许可说明。

## 6. 验收标准

- [ ] 摩托限行规则不再从普通摄像头数据推断，而是从独立数据仓库 manifest 加载。
- [ ] 摩托车闯禁抓拍证据与货车、压线、普通监控数据分离，并可以独立更新、固定版本和回滚。
- [ ] 没有明确摩托车限制依据的点位不会进入核心路线判断。
- [ ] 用户可以通过地图点击添加多个本地测试摄像头，并可以删除和清空。
- [ ] 测试摄像头刷新页面后可恢复，且不会写入公共数据仓库。
- [ ] 起点和终点都可以重新选择、删除，操作后旧路线不会残留。
- [ ] 地图显示广州行政边界和真实路网覆盖范围，不再以矩形作为唯一范围表达。
- [ ] 路网数据的目标范围包含广州行政区内的南沙区域；若局部没有可用 graph，页面明确提示。
- [ ] 正式页面不再显示 Spike 入口，Spike 直接 URL 仍可用于开发验证。
- [ ] `npm test` 和 `npm run build` 通过。
- [ ] 测试环境完成浏览器冒烟测试：加载 CDN 数据、添加测试点、修改起终点、超出范围提示和路线重新规划。

## 7. 依赖、风险与回滚

### 依赖

- 获取可再分发的广州行政边界 GeoJSON，并确认来源和许可。
- 重新生成包含南沙的广州路网 graph 和覆盖范围 GeoJSON。
- 扩展 `PeiXiu-routing-data` 的发布脚本和 manifest schema。
- 为地图覆盖范围和测试点增加前端图层及状态管理。

### 风险

- 行政边界来源可能与 OSM 路网边界存在细微差异；必须明确两者语义，不做无依据的几何合并。
- 南沙范围扩大后，graph 体积和浏览器首次加载成本可能增加。
- jsDelivr 的缓存会造成数据更新延迟，因此稳定 manifest 必须指向可验证版本。
- 本地测试点不能混入正式摄像头数据，避免误发布。

### 回滚

- 前端保留旧 manifest 配置作为可回滚版本。
- 新 graph、摄像头数据和 GeoJSON 使用不可变版本地址。
- 数据发布异常时将稳定 manifest 恢复到上一个版本，不需要回滚前端代码。

## 8. 实施拆分与顺序

本 PRD 拆成一个 Epic 和四个子 Issue：

1. 摄像头数据外置到独立仓库并支持 CDN 加载、地图选点测试。
2. 起点和终点编辑、删除交互。
3. 广州行政边界、路网覆盖范围和南沙数据补全。
4. 隐藏正式页面 Spike 入口。

推荐顺序：先完成第 3 项的数据契约和数据准备，再并行推进第 1、2 项，最后完成第 4 项及整体验收。

## 9. 产品边界说明

行政边界和路网覆盖范围只用于表达项目范围与数据可用性。摩托限行规则必须以有效的道路交通管理依据为准；抓拍证据点位仅用于辅助提示，可能存在遗漏、延迟或误差。路线结果不构成道路通行资格、合法性或安全保证。
