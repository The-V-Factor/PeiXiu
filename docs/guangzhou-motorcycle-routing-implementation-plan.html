广州摩托车摄像头避让导航 Web/PWA 实施方案

v1.0 · 2026-08-25 · 免费、广州范围、浏览器本地路线计算、按已知摄像头点位做简单避让
执行结论：先做 Valhalla WASM Spike，再做广州图数据和摄像头点位避让。Valhalla 是首选；如果无法稳定支持浏览器图块按需加载，则评估 omt-router，并明确只能使用 car 近似摩托车。

1. 目标与边界

目标

构建一个纯静态 Web/PWA：用户打开页面后获取当前位置，点击地图选择目的地，浏览器在 Web Worker 中完成本地路线计算，并在候选路线附近发现已知摄像头点位后重新规划一条避让路线。

  • 不调用远程 /route 或其他 Routing API。
  • 路线计算在浏览器本地完成。
  • 广州作为唯一支持区域。
  • 首选 Valhalla WASM，必须实际验证 motorcycle。
  • 摄像头点位只作为风险点，不建模完整交通法规。
  • 软件、地图数据和部署优先采用免费方案。

V1 不做

  • 全国、省级或跨城市路由。
  • 地址/POI 搜索、账号、收藏、社区和后台管理。
  • 实时交通、实时摄像头同步和在线导航播报。
  • 完整禁摩法规引擎、车籍判断、时段判断和例外规则。
产品提示：路线仅供辅助参考。摄像头点位可能存在延迟、遗漏或变更，请以实际道路标志和交通法规为准。

2. 技术路线决策

方案决策原因
Valhalla WASM首选支持 motorcycle 和 exclude_locations，但浏览器图块读取和异步加载风险最高。
omt-router备用原生浏览器 Worker、图块缓存、无后端；目前只有 car/bicycle/pedestrian，使用 AGPL-3.0。
MPEE暂不选MIT/WASM，但公开 profile 主要为 car、bicycle、foot，偏单区域整体缓存。
OSRM/GraphHopper 服务不选通常需要路由服务端，不满足浏览器本地计算约束。

参考：Valhalla Route API、omt-router。

3. 总体架构

业务层只依赖统一的 RoutingEngine，不直接依赖 Valhalla JSON、Emscripten FS 或具体 npm wrapper。

4. 核心流程

5. 业务接口

export type Coordinate = { lat: number; lon: number }

export type RouteInput = {
  start: Coordinate
  end: Coordinate
  costing: "motorcycle"
  excludeLocations?: Coordinate[]
}

export type RouteResult = {
  distanceMeters: number
  durationSeconds: number
  geometry: GeoJSON.LineString
  avoidedCameraCount: number
}

export type RoutingEngine = {
  init(): Promise<void>
  route(input: RouteInput): Promise<RouteResult>
  clearCache(): Promise<void>
}

6. 摄像头点位算法

V1 只使用静态 JSON 点位。第一次路线完成后，计算摄像头点到路线的距离，筛选 200 米内的点，再把这些点传给第二次路线请求。

avoidedCameraCount 表示参与二次规划的摄像头数量，不表示法规上绝对安全。

8. 实施阶段

Phase 0：项目骨架。 Vite + TypeScript、RoutingEngine 接口、/spike 页面、调试输出。
Phase 1：Valhalla WASM Spike。 只验证浏览器启动、小规模 graph、geometry/distance/duration 和无远程 route API。
Phase 2：motorcycle 与摄像头避让。 固定起点、终点和测试摄像头点，确认第二次路线实际变化并绕开点附近道路。
Phase 3：广州 graph 和按需加载。 构建 OSM graph、发布独立数据仓库和 jsDelivr、实现缺 tile 获取和 manifest。
Phase 4：IndexedDB 缓存。 版本隔离、统计、清除缓存、失败重试。
Phase 5：MapLibre 最小 UI。 地图、定位、目的地、摄像头 GeoJSON、路线和结果面板。
Phase 6：GPS 与错误处理。 覆盖拒绝定位、超时、引擎失败、tile 失败、数据失败和无路线。
Phase 7：PWA 与免费部署。 manifest、Service Worker、Pages、jsDelivr 和固定版本缓存策略。

9. 技术路线选择流程

10. 测试与性能记录

  • 单元测试：坐标校验、摄像头解析、点到线筛选、请求生成、响应解析、缓存版本隔离。
  • 集成测试：固定 OSM PBF checksum、Valhalla commit、graphVersion、起点、终点和测试摄像头。
  • 浏览器测试：Desktop Chrome、Android Chrome、iPhone Safari。
  • 性能指标：WASM 大小、初始化耗时、首次路线耗时、tile 数量/体积、缓存后二次路线耗时。

测试关注道路和点位关系，不要求每次 graph 更新后 geometry 的每个小数位完全一致。

11. 免费部署方案

部分方案
代码GitHub 或其他免费 Git 仓库
前端Cloudflare Pages
graph tile公开路网数据仓库 + jsDelivr
地图OpenFreeMap 公共实例或自托管 OpenMapTiles
数据OpenStreetMap + 自维护摄像头 JSON
计算浏览器 WASM / JavaScript Worker

graph tile 不进入 PeiXiu 主代码仓库，使用独立公开数据仓库和 jsDelivr 的 commit URL 固定版本；发布时保留 OSM 来源、checksum、归属和许可证说明。参考：jsDelivr、Pages Limits。

12. MVP 验收标准

  • 页面显示广州地图。
  • 可点击地图设置目的地；GPS 失败时可手动选择起点。
  • 浏览器本地启动路由引擎，没有远程 route API。
  • 首选引擎使用 motorcycle，可以加载真实广州 graph tile。
  • graph tile 按需下载并有本地缓存。
  • 可以加载和显示广州摄像头 JSON。
  • 第二次摄像头避让路线实际生效。
  • 显示最终路线、距离、预计时间和已避开摄像头数量。
  • 支持 PWA 安装并部署到 Cloudflare Pages + jsDelivr。
  • 小规模使用不依赖付费 Routing API。

13. 执行原则

  1. 先做 Spike，后做 UI。
  2. 先验证能力，不根据 wrapper 类型或 README 猜测。
  3. 业务层只依赖 RoutingEngine。
  4. Valhalla 失败时切换 adapter，不重写整个应用。
  5. 摄像头避让只描述为“避开已知点位”。
  6. 所有 graph、OSM 和摄像头数据都带版本。
  7. 不引入付费地图、搜索或路线 API。
